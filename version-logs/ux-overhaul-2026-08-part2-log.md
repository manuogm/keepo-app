# UX overhaul part 2 — archived-account net worth bug, Dashboard trend, Transactions toolbar cleanup

Follow-on to `ux-overhaul-2026-08-remove-insights-fi-log.md`, same session family. Six items from a fresh round of user feedback after that batch shipped.

## What shipped

1. **Archived accounts no longer count toward net worth (real bug, not a display tweak).** `account_balances_base`/`net_worth()` never filtered `archived_at` — the original `archive_account` migration's own comment (20260805180000) flagged this as "a later phase's job" and it never landed. Fixed at the source in `20260820100000_archived_account_net_worth_exclusion.sql`:
   - `account_balances_base` gains a trailing `archived_at` column (append-only view rule — the 7 existing columns are untouched).
   - `net_worth()`'s three scope branches (`me`/`household`/`total`) now filter `where ab.archived_at is null`.
   - `account_balances` itself is deliberately left alone — an archived account's own balance must still resolve correctly wherever it's shown individually (AccountFormView, ArchiveAccountsView), just not summed into the total.
   - Mirrored locally in `LocalMoneyConversion.scopedAccountIds` (adds `AND archived_at IS NULL` — the one shared place both `netWorth` and `netWorthSeries` pull account ids from).
   - pgTAP: new assertion in `06_account_lifecycle.sql` (archive an account mid-suite, assert `net_worth('total')` drops to just the still-active account).
   - Swift: new `KeepoTests/LocalMoneyConversionArchivedAccountTests.swift`, seeded independently of the referee fixture (didn't want to touch the pinned Postgres-capture fixture for this).

2. **Archived-account transactions drop out of the main Transactions list — no physical flag added.** Considered giving every transaction its own `archived` flag mirroring the account, rejected it: that needs active sync on archive/unarchive and can drift. Instead `LocalTransactionRow.fetchFiltered`'s account join gained `AND a.archived_at IS NULL`, exactly the pattern `deleted_at` already used — visibility is derived live from the account's own state, the FK is untouched, unarchiving makes the rows reappear with zero backfill. Covered by the same new test file.

3. **Dashboard notifications panel now grows from the bell button.** Swapped `.sheet(isPresented:)` for `.popover(isPresented:)` anchored directly to the bell `Button`, with `.presentationCompactAdaptation(.popover)` (iOS 16.4+) — without that modifier a popover collapses to a full-screen cover in iPhone's compact width class, which is exactly the "regular modal rising from below" look the user wanted gone.

4. **Net worth card: shorter, month-over-month trend badge, stock-style chart.** `NetWorthChartView` gained a `trendColor` parameter driving both the `LineMark`'s color and a new `AreaMark` gradient fill underneath (`trendColor.opacity(0.25)` → clear). New shared `TrendBadge` view (also in `NetWorthChartView.swift`) shows `±X.X% this month` or `—` when unresolvable (money rule 5 — a missing FX rate must never render as a fake 0% or a silently-wrong percentage). Both `HomeView`'s card and `NetWorthDetailView` compute `monthOverMonthChange`/`trendColor` the same way and pass the same color into the chart — the two `load()` functions already duplicated the whole netWorth-loading call before this change (2 call sites, consistent with CLAUDE.md's "don't extract before a third"), so the small addition stayed duplicated rather than introducing a shared load helper neither screen asked for.

5. **Transactions: the non-functional "..." button is gone.** It was the filter icon under `.secondaryAction` — with only one item there, iOS collapses it into an overflow "More" button whose icon-only label renders with no visible text inside the resulting menu row, which is almost certainly why it read as broken. Removed the toolbar item, `isFilterSheetPresented`, `filterIconName`, the now-fully-orphaned `TransactionFilterView.swift`, and `filterAccounts` (only ever fed that sheet). `TransactionFilter`'s `accountId`/`categoryId`/`kind` fields and the SQL branches that consume them were deliberately left in `TransactionFilter.swift`/`LocalTransactionRow.swift` — they're a legitimate general-purpose filter shape, not dead code tied to the deleted UI, and CLAUDE.md's simplicity principle argues against ripping out working, reusable plumbing on a guess about future need either way.

6. **+/search toolbar order swapped**, per explicit request — declaration order in `.toolbar` reversed (search now declared first).

## Findings for the next agent

- **`supabase test db --local` does NOT apply pending migrations on its own.** It runs pgTAP against whatever the local Postgres container's `supabase_migrations.schema_migrations` table already has — a new migration file sitting in `supabase/migrations/` is invisible to it until `supabase db reset` replays the full migration chain. `supabase migration list --local` is not a reliable "is it applied" check either: it lists local *files* against the remote table, not local *applied* state — its `"local"` column can show a migration that was never actually run against the local db. Ground truth is `docker exec <container> psql -U postgres -d postgres -c "select version from supabase_migrations.schema_migrations order by version desc limit 5"` (container name via `docker ps | grep supabase_db`) or just always `supabase db reset` before `supabase test db --local` after adding a migration.
- **`supabase gen types swift` redirect gotcha (recurrence, third time this project) has a real fix, not just a manual strip.** Previous sessions hit this by capturing a combined stdout+stderr stream (`> file 2>&1`), which put the CLI's own `Connecting to db 5432` status line at the top of the generated Swift file. Redirecting stdout and stderr *separately* (`> out.swift 2>err.txt`) keeps the status line out of the generated file entirely — no post-hoc line-stripping needed. Don't reach for `tail -n +2` as a reflex fix; check whether line 1 is actually garbage first (this session briefly re-broke the file by blind-stripping a legitimate `import Foundation` line before catching it).
- **A `.popover` needs an explicit `.frame` on iPhone.** Without one, a `NavigationStack`-wrapped `List` inside a compact-adapted popover can render at an unpredictable/collapsed size. Gave `NeedsReviewView`'s popover content a fixed `.frame(width: 340, height: 480)`.
